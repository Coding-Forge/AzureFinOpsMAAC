Getting started

What should I run first?

Run scripts\Start-FinOpsDataPull.ps1. Use the launcher to select subscriptions, set output/history locations, enter agreement metadata, and start the export.

What permissions do I need?

The signed-in Azure CLI identity needs access to list subscriptions, read resource groups, and query Azure Cost Management for selected subscriptions. Cloud uploads require data-plane write permissions to the selected Blob container or ADLS Gen2 file system.

Do I need Azure CLI?

Yes. The launcher uses Azure CLI for sign-in, subscription discovery, resource group export, and cloud uploads. The launcher can help install it if winget is available.

Output and history

What is OutputRoot?

OutputRoot is the timestamped run folder for one export, such as C:\Projects\Fabric\AuditDumps\run-20260630-162906. Power BI's LocalDataRoot should point to a completed run folder.

What is HistoryRoot?

HistoryRoot is the durable folder shared across runs, such as C:\Projects\Fabric\AuditDumps\history. It stores long-term files such as cost-retail-history.csv and macc-benefit-ledger.csv.

Why are some tables blank?

Blank tables usually mean Power BI is pointed at a failed or header-only run folder, or the table is a customer-maintained template. Rerun the export successfully and update Power BI parameters to the completed run folder. BillingReconciliation and OwnershipMapping stay blank until users fill their CSV files.

Power BI refresh

Which file tells me the Power BI parameter values?

Open powerbi-storage-settings.json in the run folder. Copy its values into the Power BI parameters for StorageLocation, LocalDataRoot, HistoryDataRoot, and any cloud root values that apply.

Why do I get missing CSV errors?

The selected run folder does not contain the expected generated files. This often happens after an export failure, timeout, or when Power BI points to the parent output folder instead of a timestamped run folder.

Why do I see schema or TMDL errors?

Use the latest solution files and reopen the PBIP after pulling changes. Generated report pages must follow the enhanced PBIP JSON schema, and model expressions must stay in valid TMDL format.

MACC audit and reporting

Which pages should executives use?

Start with MACC Commitment Overview for utilization, remaining commitment, pacing, and required monthly run rate. Use MACC Benefit Ledger for long-term savings trends.

Which page explains how savings were calculated?

Use Agreement Price Audit. It shows actual cost, effective unit cost, retail price, retail equivalent cost, estimated savings, match status, and retail SKU/meter evidence.

How should I handle unmatched retail rows?

Use Coverage and Exceptions. Review rows with high actual cost first, then update retail-match-exceptions.csv with owner, review status, resolution, and notes if you want dispositions to round-trip into Power BI.

Does this retrieve the official MACC balance?

No. Commitment burn-down is calculated from customer-provided agreement metadata and exported cost data. Treat it as governance analysis and reconcile it with official billing/agreement records.

Troubleshooting commands

Run these from the solution root when troubleshooting script or release packaging issues. 
Set-Location 'C:\Projects\Fabric\AzureFinOpsMaccRetailSolution'

# Parse the launcher
$tokens = $null
$errors = $null
[System.Management.Automation.Language.Parser]::ParseFile(
  (Resolve-Path 'scripts\Start-FinOpsDataPull.ps1'),
  [ref]$tokens,
  [ref]$errors
) | Out-Null
$errors

# Build a local smoke release without zip
.\build-release.ps1 -Version dev-smoke -Force -NoZip
