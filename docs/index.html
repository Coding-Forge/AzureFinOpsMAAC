What this solution does

Azure cost conversations often require data from Cost Management, Billing, subscriptions, resource metadata, public retail prices, customer agreement context, and Power BI. This solution brings those signals together so teams can inspect spend, explain cost drivers, estimate retail-equivalent pricing, and review MACC consumption in one repeatable workflow.

Cost and usage extraction Pulls Azure Cost Management data by subscription, service, resource group, region, meter, product, and usage date.
Retail price comparison Matches usage to Azure Retail Prices API metadata to estimate retail-equivalent cost and potential savings.
MACC pacing Produces agreement status, benefit ledger, commitment pacing, and exception artifacts for review.
Billing evidence Exports billing account, profile, invoice section, subscription billing property, invoice, and billing-role evidence where permissions allow.
Multi-cloud support Tracks Azure Commercial and Azure Government data with cloud-aware history, subscriptions, and region dimensions.
Operational monitoring Supports Azure SQL durable-store views for ingestion freshness, row counts, retail match coverage, and run health.

Who it is for

The project is intended for cloud solution architects, FinOps practitioners, account teams, and technical owners who need a repeatable way to collect and discuss Azure cost evidence. It is also useful as a starting point for enterprise teams that want to operationalize cost ingestion into Azure SQL and Power BI.

This is not a replacement for official invoices, contract systems, or Microsoft billing portals. Treat retail-equivalent pricing and savings as directional analysis that should be validated before customer-facing commitments.

Use it locally

The local workflow is designed for development, proof of concept, or one-off analysis from a workstation with PowerShell, Azure CLI, and Power BI Desktop.

  1. Clone the repository.
  2. Sign in to the target Azure tenant with appropriate read permissions.
  3. Run the prerequisite checker.
  4. Start the launcher and select subscriptions, analysis mode, agreement details, and output location.
  5. Open the generated Power BI template and provide the generated parameter values.
powershell.exe -NoProfile -ExecutionPolicy Bypass `
  -File .\scripts\Test-FinOpsPrerequisites.ps1 `
  -AzureCloud AzureCloud `
  -CheckPowerBiDesktop

powershell.exe -NoProfile -ExecutionPolicy Bypass `
  -File .\scripts\Start-FinOpsDataPull.ps1

Each run creates a timestamped output folder with logs, CSV/JSON outputs, audit artifacts, and a powerbi-storage-settings.json file that tells Power BI which parameters to use.

Use it as an enterprise solution

The enterprise path keeps local scripts available for development and proof of concept, but moves the system of record and scheduled operations into Azure.

Reference architecture

  • Azure Function App for scheduled ingestion.
  • Managed identity as the preferred production authentication mode.
  • Azure SQL Database as a governed durable store.
  • Optional Azure SQL private endpoint and Function VNet integration.
  • Optional Key Vault references for service-principal secrets when managed identity is not possible.
  • Application Insights and Azure Monitor alerts for failed or missed runs.

Deployment building blocks

  • infra\bicep\main.bicep deploys core Azure resources.
  • infra\bicep\role-assignments.bicep assigns subscription-scope RBAC to the Function identity.
  • scripts\Deploy-FinOpsSqlSchema.ps1 deploys SQL tables and monitoring views.
  • scripts\Import-FinOpsSqlData.ps1 loads durable history into SQL.
  • functionapp\ contains the timer-triggered ingestion scaffold.
az deployment group create `
  --resource-group "<resource-group>" `
  --template-file .\infra\bicep\main.bicep `
  --parameters .\infra\bicep\main.parameters.json

For private-network deployments, run SQL schema deployment and SQL smoke tests from a Bastion-accessed jump box, VPN/ExpressRoute-connected workstation, or self-hosted deployment agent inside the VNet.

Local versus enterprise mode

Capability Local / POC Enterprise-ready path
Execution PowerShell launcher on a workstation. Azure Function timer trigger using native Az.Accounts and REST calls.
Authentication Interactive Azure CLI or existing local context. Managed identity by default; Key Vault-backed service principal if required.
Storage Local run folders and durable CSV history. Azure SQL durable store with monitoring views and optional private endpoint.
Reporting Power BI template reading generated files. Power BI template plus optional SQL-backed operational freshness page.
Operations Manual review of logs and output files. Application Insights status markers and Azure Monitor alerts.

Important notes

  • Generated exports can contain sensitive billing, subscription, and tenant information. Do not commit generated outputs.
  • PBIP source projects are intended for local development and are not included in the public repository.
  • Public releases should use a sanitized PBIT template that prompts for parameters instead of embedding local paths or customer data.
  • Azure Government and GCC High scenarios require validation of Cost Management, Billing, Retail Prices, storage, and Power BI behavior for the target tenant.
  • Retail price matching is directional and may not represent contracted, discounted, or government-specific pricing.
